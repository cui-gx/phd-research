## 3. 反馈量与事件边界（本项目约定）

“模型反馈被采用”指：下一段MD的起点来自一次有记录的选择结果，该选择结果带有模型版本ID。**MD求解器本身不运行CVAE。** 文中的“消费模型”只允许作为此版本关系的简称。

| 首选名称 | 符号、单位 | 操作性定义 |
|---|---|---|
| 有效MD结果 | 结果ID，计数 | 任务正常返回、输出可读、原子映射和配置匹配、轨迹/数值通过预定完整性检查。工程上有效不表示已达到科学目标。具体验证项随运行清单冻结。 |
| 训练数据快照 | snapshot ID / hash | 某次训练实际接收的数据清单及版本，派发时保存；规则固定不要求所有策略得到相同数据。 |
| 已采用模型版本 | v(t)，版本ID | 不晚于t的最近一次MD起点派发所追溯到的模型版本；初始化阶段无版本，记NA。 |
| 未纳入已采用模型训练的结果数 | B(t)，个MD结果 | 已完成有效MD结果中，不在v(t)训练快照内的结果数量。它们可能已被旧模型推理使用，所以**不称“完全未使用数据量”**。 |
| 已采用模型的数据年龄 | A(t)，墙钟秒 | t减去v(t)训练快照内最新数据的可用时间。无v(t)则NA。不同于模型发布后经过时间，也不同于排队时长。 |
| 模型发布年龄 | 秒，诊断量 | 当前时刻减模型发布时刻；不能与A(t)互换。 |
| 模型到排名发布延迟 | 墙钟秒 | 模型可用到使用该模型的起点排名发布；须有模型ID关联。 |
| 排名到首次采用延迟 | 墙钟秒 | 排名发布到首次从该排名派发MD起点；未采用记未完成/删失。 |
| 重训反馈链延迟 | 墙钟秒 | 某结果可用→进入训练快照→模型发布→排名发布→MD起点首次采用的可追溯链。未进入后续环节的不填0。 |
| 选择反馈链 | 事件链 | 新轨迹也可由旧模型编码后进入新排名；这条路径不经过新模型训练，单独记录，不能假定所有反馈必须先重训。 |
| 反馈状态 | 状态向量 | 在决策时刻可观察的B、A、版本和事件进度；是概括名，使用时必须列具体字段。 |
| 反馈门控 | 条件规则 / feedback gating | 根据规定反馈阈值决定是否提高已就绪学习任务优先级；不创造训练请求或改变模型配置。 |

版本关系能证明数据/模型被哪个流程采用，不能单凭关联证明某条数据对科学结果具有单独因果效应。

## 4. 时间、指标与证据

| 首选名称 | 日语 / 符号与单位 | 定义和禁止混用 |
|---|---|---|
| 物理模拟时间 | 物理シミュレーション時間 / ps、ns | 积分覆盖的分子物理时长；10ns不表示服务器运行10ns。 |
| 墙钟时间 | 実経過時間 / s、h | 机器实际经过时间。H、排队和反馈延迟用此口径。 |
| 观测截止时间 | 観測終了時刻 / H | 从共同t0起的观测及新任务接纳截止；H停止新派发，已运行任务自然排空至各自超时。H后才可用的输出只诊断，不计窗口内达标。H不是正常强杀时刻。 |
| 近天然构象目标达标率 | 近天然構造目標の達成率 / P_success(H) | H内达标campaign数/按预定纳入规则确定的campaign数；不用“模型准确率”代称。 |
| 首次达标时间 | 初回目標達成時間 / T_hit，墙钟秒 | 首个有效连续轨迹满足目标且结果可用、完成检查的时间。未在H内达标则右删失。 |
| 右删失 | 右側打切り / right censoring | 截止时尚未观察到目标事件；不等于在H时成功，不删除失败样本。 |
| 最佳RMSD进展 | 最良RMSDの推移 / best-so-far RMSD，Å | 截至t已可用有效帧中的最小RMSD；单帧最小值不等于持续达标。 |
| MD吞吐 | MDスループット / ns per wall-clock hour | 单位实际时间内完成的物理模拟量；不是科学成功率。 |
| GPU利用率 | GPU使用率 / utilization，% | 指定采样工具/周期下的忙碌程度；与占卡、显存占用、科学成果分开。 |
| GPU预留时间 | GPU確保時間 / reserved GPU-hours | 卡数×预留墙钟小时，包含预留期间闲置；H内和含排空费用分别报告。记录完整费用不能以忙碌时间替代。 |
| 排空 | 実行中タスクの終了待ち / drain | H到期、smoke成功或停止接纳后，等待运行任务自然结束至各自单任务超时；仍占用资源并计费。STOP、任务错误、存储/RSS超限或任务超时才强制停止本次自己的任务。 |
| 训练损失 | 学習損失 / training loss | CVAE重建与KL目标值；不是折叠准确率或科学收益。 |
| 完整策略效应 | 方策全体の効果 / whole-policy effect | 两种完整调度策略下campaign结果的差异；不等于同一状态下某个单动作的因果效应。 |
| 基线 | 比較手法 / baseline | 合理配置并公平获得开发预算的比较方法；不能故意削弱。 |
| 消融 | 要素除去比較 / ablation | 有控制地移除一项机制/信息的比较；其他实现条件一致。 |
| 提案值 / 冻结值 / 实测值 | 提案値 / 事前固定値 / 実測値 | 分别是拟定参数、正式实验前锁定参数、运行所得数值；三个状态必须写明。 |

单位：1Å=0.1nm；1ns=1000ps；当前2fs=0.002ps。近天然目标的2Å/100ps是提案，按10ps帧间隔需11帧覆盖100ps，且来自同一连续段。CPU核须注明物理核或逻辑线程；GPU的96GB为清单标称，实机工具读数及其单位另记。

证据标签沿用AGENTS的四种：`derived analysis`、`local CPU/GPU measurement`、`trace-driven simulation`、`small Slurm/pilot testbed`。此表与当前未运行提案属于第一种。

## 6. 上机实现补充（v2，2026-10-23）

本补充固定工程事件含义，不改变v1中的B/A、几何目标、统计分母；具体实现见 `p1/server/` 和 `上机准备/2026-10-23-P1/实验协议与判据.md`。当前版本修正v1.1中“截止取消任务”的实现说明，正常截止改为停止派发后自然排空；异常停止单独处理。

| 中文 / 日语 / English | 操作定义、单位与边界 |
|---|---|
| 功能检查 / 機能確認 / functional smoke test | 用缩短工作量检查真实函数、文件与版本链能否接通。当前CPU功能配置为2ps、0.05ps输出间隔、40帧、1epoch；目标GPU资格配置仍为20ps、0.5ps输出间隔、40帧、1epoch。两者不能混作同一性能实验，均不能估计正式科学收益。 |
| 上机资格检查 / 実機適合確認 / machine qualification | 确认实际许可、资源、CUDA、科学输入/输出及闭环事件有效；不等于策略显著优于基线。 |
| 任务接纳 / タスク受入れ / task admission | 将已就绪的完整任务交给一个空闲GPU执行槽；本实现与dispatch同一事件边界。不同于运行中缩放。 |
| GPU执行槽 / GPU実行スロット / GPU execution slot | 资格原型每卡至多一个任务的工程限制；不是GPU物理不可并发的事实。必须完成同卡并发资格后才能固定论文共同基座。 |
| 归一化等待值 / 正規化待ち時間 / normalized waiting value | (当前墙钟秒−就绪墙钟秒)/预计任务墙钟秒，无量纲；F0原型选最大者，稳定ID打破并列。预计耗时不是未来真值。 |
| 逻辑CPU集合 / 論理CPU集合 / CPU affinity set | 许可的操作系统CPU编号集合，不能直接叫物理核数。集合第一项固定给控制器及Parsl主进程线程，两路任务仅使用其余互不重叠的CPU。当前两任务各2线程最低需5个许可逻辑CPU；Linux亲和性需实测，macOS功能检查不能证明此项。 |
| 运行许可时限 / 利用許可の期限 / lease expiry | 许可必须覆盖H＋单任务超时＋30秒清理余量；它不延长科学观测窗。当前GPU资格的15分钟H和5分钟任务超时至少需20分30秒剩余许可时间。 |
