# 共通歴史、データ系譜、時刻合法性

## 入力と物理条件

FSD-EY/1FMEの固定DeepDriveMD unfolded入力SHAは事前計画に記載した。504原子/28残基。新seed2026102660でNoCutoff/Amber14-all/GBn2、300 K、2 fs、Langevin摩擦1 ps⁻¹、HBonds許容10⁻⁵、CUDA mixed/DeterministicForces=trueを使う。入力の生成・pH・質子化履歴が完全に認証されたわけではない。[GQの物理監査](../P1-GQ/physics-protocol.md)の限界を継承する。

旧2 nsを完了して全点品質を検査し、旧poolを公開してM0を学習する。その後に同じOpenMM完全checkpointから2 nsを継続する。継続時に最小化や速度生成を行わず、座標/速度/確率流/物理時間を復元する。中間に学習を挟む壁時計の休止はMD物理時間を進めない。

M0は旧データだけを読む。新データは生成も公開もM0より後である。M0に渡したファイル・抽出ID・SHAは残り、後に最終poolへ書き換えない。旧S2の1 nmや既存GQ軌跡は学習poolへ混ぜていない。過去R2の品質定義だけを再利用したことと、学習データを混ぜることは異なる。

## 固定split

| 役割 | 物理時刻 ps | 抽出 |
|---|---|---|
| M0/F1旧学習 | 100<t≤1600 | 等間隔800適格ID |
| 共通validation | 1700<t≤2000 | 等間隔200、学習と100 psの間隔 |
| F2旧成分 | 旧800の偶数位置 | 400 |
| F2新成分 | 2000<t≤3600 | 等間隔400 |
| 共通候補P_t/A0 | 100<t≤4000 | 適格全7,800フレーム |

validationは同一履歴の時間区間であり独立campaignではない。候補池と学習入力はオンライン決定として重なってよいが、その重なりをモデルの汎化精度評価に使わない。重複する接触特徴と同一構造/同一IDも区別する。

## 保存物と時計

全フレームの元区間、0起点global ID、各区間local ID、物理時刻、DCD/PDB/System/特徴SHA、学習露出と候補順位を保存する。frame<4000は旧区間、その後は新区間でlocal=global−4000。下流初期座標は選点されたDCDから全原子で抽出し、実際のContext入力配列と照合する。

イベントの`at_s`は同じcampaignの単調時計、UTCは監査用、物理psとは別である。MDの生出力公開後に品質処理を行い、その成功で資格確定を公開する。学習はその後にしか開始しない。モデル/ランキングの公開と次MDでの採用も別イベントである。

[凍結記録](recipe-freeze.md)と実行eventsの対応で時刻合法性を確認する。大DCD/重み/フレーム配列は本人サーバとSHA確認済みバックアップに保存し、GitHubに原データが存在すると主張しない。
