# 失敗・復元・修訂の記録

2026-10-26。結果を見て配方や選点を変えない。

- 最初のM0は既存校正ヘルパー `supplement_selection` のサーバ配備漏れで、学習開始前にModuleNotFoundErrorとなった。GPU占槽の監督時間1.736253秒、MD/学習結果による再実行ではない。前2 nsと品質処理/旧poolは成功しており再生成しない。
- 元M0ディレクトリ、失敗JSON/標準エラー/実行記録を保持する。既存ヘルパーを追加配備し、M0-attempt2を論理M0に対応付ける。シード、旧pool、200歩/800曝光、モデル/optimizerは同じ事前条件。対応表と新ソースSHAを原manifestとは別の修訂記録に保存する。
- 次の事前テストには復元ヘルパーimport検査を追加。科学条件、下流の候補池・乱数・MD長・評価指標は変更しない。旧S1/S2/GQ/R2の原証拠を変更しない。
- 事前計画の簡略なd式は、既存R2定義どおり `sqrt((1/325)Σ_k(D_k(x)−D_k(y))²)` を意味する。平均差の絶対値ではない。実装は最初からR2の同じdRMSDで、科学定義や尺度を変更していない。
- 下流結果の前に、費用集計で既知の失敗M0を欠損成功データとして扱わないよう明示した。失敗分も占槽費用に含める。
- 物理時刻は保存されたStateDataReporterの値で、整数stepに対し微小な浮動小数累積差がある。prefix上端は10⁻⁵ psの数値許容、burn-in下端は登録どおり厳密比較。元時刻を修写せず、丸め差を独立の科学変化に数えない。
