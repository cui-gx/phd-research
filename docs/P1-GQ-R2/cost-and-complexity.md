# CPU費用と計算量

## 実行条件と実測

全て研究室サーバのCPU実行。論理CPU0/1/2、数値スレッド2、プロセス仮想メモリ/監視RSS上限16 GiB、各段階2400秒。共有資源を各段階前に再確認した。CPU解析環境のみ復元し、CUDA_VISIBLE_DEVICES=-1、GPU Context作成なし。GPU計算は0秒でありR1残GPU時間を使っていない。

| 段階 | 監督側壁時計秒 | 処理内CPU秒 | 処理内ピークRSS KiB |
|---|---:|---:|---:|
| 全点品質検査 | 36.521 | 36.035 | 227,680 |
| 初回校正失敗 | 1.551 | 別失敗記録参照 | 別失敗記録参照 |
| 修正版校正 | 1.552 | 1.296 | 203,532 |
| 1,536条件＋固定庫 | 104.162 | 104.021 | 266,708 |
| 負対照＋小標本厳密参照 | 6.285 | 5.900 | 206,780 |
| 日本語図3点 | 2.067 | 2.057 | 234,312 |

合計監督時間152.139秒は上記6実行だけ。環境復元、テスト、文書作成、証拠整理/ハッシュ、バックアップを含む全作業時間ではない。0.5秒間隔の監督RSSピーク264,237,056 byteと処理内ru_maxrssは測定法が違うため同一値とは限らない。大きい方も16 GiB以下。

証拠整理前後の計測時点では解析資料344,077,690 byte、隔離環境501,470,566 byte。5 GiB上限以内。後に作るアーカイブ等は終了確認に別記し、環境を清掃する。

## 距離計算

特徴次元m=325。Aの代表数Kなら単純貪欲走査はO(NKm)、代表/配列の記憶はO(Nm)。履歴M点との最近傍はO(NMm)、64点ずつの照合で一時行列O(64M)。全32,000²行列は作成していない。厳密小行列は最大512²に限定した。

τを変えた結果を再利用して高速化していないため、全グリッドの時間を単一オンライン評価の時間と誤認しない。固定ライブラリには最大3,678代表があり、細尺度ほど照合費用が増える。

共通履歴の全2,000点に対し将来1,500点を厳密最近傍照合したCPU時間は壁時計0.307–0.312秒/系列。特徴生成、全原子品質確認、ファイルI/O、データ公開はこのbenchmarkに含まれず、実運用のフィードバックコストとして別に計測・加算する必要がある。GPU上MDの速度改善を意味しない。

全品質検査36.5秒は16 ns保存データに対する一括CPU後処理。GPU計算と重ならないと仮定した場合のクリティカルパスを無視できない。将来のB2ではCPU費用・データ準備・公表/資格判定も含め、実際の依存経路として計測する。本輪はその方策比較を行っていない。

証拠：[検証要約](../执行证据/2026-10-26-gq-r2/validation.json)、[*-execution.jsonおよび*-runtime.json](../执行证据/2026-10-26-gq-r2/)、[履歴距離benchmark](../执行证据/2026-10-26-gq-r2/history-distance-benchmark.json)、[完全依存lock](../执行证据/2026-10-26-gq-r2/requirements.lock.txt)。

履歴benchmarkは最初の1 ns全2,000点を用い、100 ps緩和除外を適用しない演算費用試験である。将来の成果評価A₀では、別途固定した品質・緩和規則に合わせる。最終清掃前の追加ファイル量はアーカイブを含め1,069,933,080 byte、5 GiB以下だった。清掃後も全証拠とアーカイブを保持する。
