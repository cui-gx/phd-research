## 転送用本文

推奨モデルはSol、推論High。研究者の明示的なQ0承認を確認し、GitHub mainを取得してAGENTS、全局総档案、協作交接、P1-Post-R1-Qualificationの全資料を読む。今回許可する範囲は、以下に限定する。

1. サーバ接続後に他利用者のCPU/RAM/GPU/予約を読取確認する。GPU不可視、CPU一worker・数値thread1、追加RAM2GiB、出力1GiB、2時間で停止して状況審査。既存本人領域のみ利用し、共有環境を変更しない。接続失敗はVPNを依頼し、別原因を探さない。
2. B1/R1原入力と原archiveの参照先を既存manifestから確認する。必要な小型ログだけをSHAで検証する。9archiveの削除・全量Mac転送・不要な全量展開をしない。不一致・欠落は保存して停止し、再生成しない。
3. 80モデルのrecipe、exposure、loss、resultを読み、M0/F1/F2・根/状態・seed・親/optimizer・実歩数・データIDを小型CSV/JSONへ結合する。200のper-step記録と末尾validationをそのまま保存する。train/val total、BCE、KLを区別し、BCEのsample/要素正規化は別列と式を付ける。集約値から復元できないsample-weighted KLを推測しない。
4. 訓練モードとevalモード、batch4対64/末尾8の違いを明示する。学習曲線の記述を行っても収束・汎化・科学利益のPASS判定にはしない。保持blockや基準モデルの新推論は不可。
5. 既存32履歴segmentと240下流枝のsim.csv、request、品質記録だけから、時間/stepの連続性、有限値、温度・勢能の既存時系列、初期0/100/200/500ps窓の記述を作る。物理設定変更、DCD再処理、新しい探索成果の計算、新規平衡時間の最適化は行わない。短時の安定を大域平衡とはしない。
6. 入力PDB・既存inventory・ソース・上流準備資料を確認し、pH/端基/水素・初期構造の出所の「分かる/分からない」を表にする。ログにない準備法を補わない。
7. 新規の独立出力ディレクトリに日本語報告、loss/MDログ小型表、失敗/欠測表、原SHA索引、費用、A–G引継ぎを保存する。旧B1/R1のデータ・表・報告・凍結コードは不変。

MD、CVAE訓練、CPU/GPUモデル推論、LOF再fit、新しい成果評価、B2、正式C予測器、S3は禁止。Q0が完了してもL/P/O/N/C計算へ進まない。

受入れ条件は、80モデルと272 MD taskのログ存在/欠測、実SHA、ID/時間合法性、損失の単位/集約境界、全ての失敗と制限が独立に追えること。科学的PASSを無理に出すことではない。分かった準備史と未解決事項を分け、研究者が次のP/L判断をできるようにする。
