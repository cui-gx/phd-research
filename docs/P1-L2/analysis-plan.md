# L2事前分析計画

2026-10-29。CONFIRMEDは研究者による設計依頼と対象・禁止範囲であり、以下のseed、対照、判定規則、資源案はすべてPROPOSED。既知L1を受けた追加診断の計画であり、元B1実験の事前登録と呼ばない。

## 1. 対象と目的

FSD-EY/1FME、既存OpenMM軌跡から生成された8 Å Cα接触図、mdlearn固定CVAEを維持する。新しい科学目標やモデル構造を導入しない。将来実行する場合は既存1枚のRTX PRO 6000 Blackwell Max-Q 96GBを学習用、固定CPU条件を診断用とする。今回は実行しない。

問いは「この有限データと学習レシピの下で、学習量と初期重みの違いが、再構成・構造情報・局所潜在幾何・候補順位にどう現れるか」である。構象探索利益、収束、反応座標の物理妥当性は別の問いである。

## 3. 先にできることと、新計算の情報価値

**E0選択肢（実行未承認）**：既存L1の保存reconstruction/mu/logstdと対応する接触図を読み、固定の対応入替えを評価すれば、新訓練・新forwardなしに「フレームごとのコード対応が再構成に寄与するか」を補足できる。既存近傍・KL表はそのまま再利用できる。4状態の既存20モデルに限定する案で、80モデル全体へ自動拡張しない。保存SHA/IDが一致することが前提。

E0でも初期化と学習歩数は変化しないので、200歩不足説を判別できない。平均潜在コードの復号は新forwardが必要であり、保存配列だけで済む検査と区別する。E0を行うか、最小36chainへ進むかは研究者が選ぶ。どちらも本輪では実行しない。

**最小L2案**：3つの新初期化、単一の固定最適化乱数条件で同じchainを1600歩まで追う。初期化の影響を有限の対応差として識別し、変動が見えた場合も3seedから母集団的な「有意な初期化効果」とは言わない。更新seedの完全な交差設計は目的を限定することで省く。これが必要になれば追加24子chainを別承認する案となるが、現在の行列に含めない。

## 5. 固定データと時間の合法性

状態はr01-s4、r01-s8、r02-s4、r02-s8。根は2つで、4独立根ではない。b=2/6 ns、判断時点d=4/8 ns。原B1のOLD800、F1=OLD800、F2=OLDの固定400+NEW400を維持し、F2を「800に400追加」と記述しない。

訓練原順序はQ0 exposureのpermutation_positionから復元した[9,600 membership行](training-membership.csv)。原サーバindicesとの一致を将来の実行前に検査する。ソースのt1はmembershipを転記するための参照であり、旧t1の学習順序/seedを新実験へ流用しない。全8epochで同じ800個のunique IDを使う。

各状態OLD_VALIDATION200とRECENT_HELDOUT200をL1からそのまま転記した[1,600 ID行](evaluation-ids.csv)。OLDは(b−0.3,b]、RECENTは(b+1.7,b+2.0]の既存固定ID。新データ訓練窓は(b,b+1.6]。全臂の訓練とID非重複だが、時間相関と構造類似は残る。M0に対するRECENTはb時点より後の**事後汎化診断**で、M0を当時オンライン選択した証拠ではない。

L1の結果を既に読んだ集合を再利用するので、両集合とも開発診断用であり、未使用の独立確認集合ではない。L2を見て将来レシピを変えるなら、別根での検証を別計画にする。入力図、候補池、LOF密度集合、科学評価基準は本L2中に変更しない。

## 6. 統計階層と公開順序

歴史根→同根S4/S8→3初期化→対応M0/F1/F2→同chain checkpoint→相関フレームという階層を保持する。MDseedの新しい層はない。主要対比は各セルの値と対応差を全て示し、根内2状態・3初期化の平均を補助表示する。2根による母集団CI、フレーム/19,900距離対を独立標本としたp値、checkpointを独立seedとする検定は行わない。

初期化seedは状態間で共用する交差因子であり、12独立科学実験ではない。初期化差は固定最適化stream条件付き、F2−F1は固定親・同step条件でのデータ構成差。S8−S4は履歴・窓・候補が異なる段階条件差としてのみ報告する。B1の下流成果を結合して最適checkpointを選ばない。

実行が別途承認された場合も、設計/ID/SHA/コード・環境の凍結とGitHub回読を科学計算に先行する。全条件を完走または理由付き欠測として残し、良いセルだけの図・報告を作らない。受入れ基準の変更が必要なら実行前に別版を承認する。
