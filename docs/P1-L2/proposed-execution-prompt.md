# 研究者審査後に使う実行依頼案

**推奨：Sol High。理由：設計を固定した後の実装、SHA/系譜/乱数監査、定型表・証拠の整理が中心だからである。方法変更や解釈の重大な問題では停止し、研究者がAstra Extra Highへ切り替えて再審査する。**

この文面はPROPOSEDで、現在の計算許可ではない。研究者が36chainを明示承認する場合にだけ使用する。E0だけを承認する場合は以下を送らず、保存配列に限定した別依頼を作る。

---

推奨モデルSol、推理High。以下の範囲を研究者が別途承認した時点で、指定された承認済み設計commitと最新mainを照合して開始する。承認commitが指定されていなければ科学計算を開始しない。

AGENTS.md、collaboration-policy、全局档案、協作交接、docs/P1-L2の全設計とID/行列を読む。36chain（4既知状態×3初期化×M0/F1/F2）、200/400/800/1600追加歩、M0-step0対照、固定M0-200親を厳守する。新MDなし。旧B1/R1/Q0/L1と9原archiveは不変。Mac原backup免除は維持する。

サーバ接続時と各計算開始前に他利用者・予約・CPU/RAM/GPUを確認する。許可領域以外を変更しない。VPN失敗時は研究者へ連絡する。単worker/数値thread1、CPU評価GPU不可視、既存単GPUのみ学習、提案カードで承認されたメモリ/出力保護と2時間復核点を守る。

まず使用入力の実SHA、原子順、frame ID/時刻、800訓練ID、共通OLD/RECENT200ずつ、FULL候補7,800/15,800と原indicesを検証する。原資料/凍結コードを編集せず、独立L2 adapterを作る。人工tensorで保存/再開・評価と訓練RNGの分離・歩数を検査し、設計/実装/環境/順序/RNG仕様をGitHubへpush・回読してから科学計算する。

初期化とoptimization/permutation seedを区別し、全F1/F2の親model/optimizer SHA、初期RNG対応を確認する。中間checkpointは同一chainの繰返し測定として扱う。全raw loss/BCE/KL/提示ID、実資源費用、故障/欠測を保存する。訓練構造・損失・batch・lrを変更しない。最良親やseedを選ばない。

全156endpointで固定の二集合・三mask・頻度/平均コード/対応入替え/未学習/幾何・seed安定性を評価し、FULL LOFの全score/rank/Top1を保存する。新Top1はNOT_OBSERVED。B1の下流成果をモデル選択や新成果へ流用しない。結果は2根の探索的診断とし、収束・探索利益・C/B2を認定しない。

入力不一致・非有限・条件変更の必要・資源復核点で停止し、理由と成功/未完了数を報告する。無断増量・自動seed差替え・成功出力上書きをしない。

完了時は全モデル/状態/対比の表、日語review-dossier、A–G引継ぎ、費用/失敗/原資料不変監査、SHAと再現手順を作る。最新mainを再取得・整合後commit/push、遠隔全文回読して真のSHAを報告し停止する。L2/P/O/C/B2/S3の後続を自動開始しない。
