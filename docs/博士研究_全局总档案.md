1. **当前 P1 已经明确研究对象**，不再建议重新选择蛋白质、软件或主问题。它以 **FSD-EY (PDB: 1FME) + OpenMM + CVAE + DeepDriveMD/Colmena** 为工作流，研究固定计算时间里 MD 计算与 AI 学习/推理的执行时序如何影响构象空间探索。原设想 2 GPU，2026-10-23 更改为 **1× RTX PRO 6000 96GB**。

3. **“预测”原本的重要含义是单次科学工作流内部的决策预测**：已有新 MD 数据时，估计更新 CVAE 的未来收益、更新能否改变候选起点选择，以及剩余计算时间是否足以兑现科学收益，决定何时训练、何时继续模拟。**不要自动把用户的预测计划改写成“预测 HPC 集群中未来提交多少作业/负载峰值”。** 后者曾作为助理扩展设想讨论过，但不是用户本轮所指的主要预测方向。
4. **总体长期愿景**：固定、有限的计算资源下帮助科研机构完成更多有效工作；共享单个异构 HPC 集群是三年总体系统设想，涉及不同 CPU/GPU 类型、任务放置、资源数量、队列调度与公平性；**这不代表 P1 必须做异构集群调度**。

## 1. 用户已确认的总体科研动机与原则

### 1.1 动机

- AI 计算需求增长、计算硬件与能源成本受到关注；传统科学计算即便完全不需要大语言模型，仍可能是计算密集型。
- 希望有限科研预算和硬件资源得到更有效利用，让更多研究团队完成更多有效计算，而不是单纯提高 GPU 利用率或研究 AI 模型本身。
- 主要目标选择了 **B：在有限资源的基础上得到更多成果 / 让更多科研任务获得计算机会**，而非以能耗或成本最小化为唯一目标。
- 长期有兴趣使用历史统计学习未来更优决策；多类型异构 CPU/GPU 硬件分配也必须出现在博士总体规划中。

### 1.2 总体系统边界（已确认的设计取向；非 P1 实验范围）

- 研究域选择 **B：单个共享的异构 HPC 集群**，不是跨云/跨研究机构资源迁移。
- 用户授权模式选择 **B：科研用户声明合法可选硬件、资源上下限与必要约束；调度器在许可范围内优化**。不得假定任意 CUDA/MPI 任务可无损扩缩容、迁移或变更硬件。
- 时间尺度选择 **C：长期统计与学习辅助短期在线调度**。当前队列/作业状态与历史信息都可供决策；**不必把预测“未来任务到达率”定成主贡献**。
- 可仿真优先，**不以当前能否申请真实 HPC 集群或 Slurm 管理权限作为必要前提**；可用受控性能测量、公开日志/测量、离散事件仿真，并须区分真实证据与模型假设。
- 与已有传统/先进调度方法使用**同样的资源容量、任务集合、到达过程、用户约束与计算预算**比较。指标需与目标一致，注意任务规模差异、性能退化、公平性、资源配置开销。
- 不要求一开始重写 Slurm，也不要求 P1 实现 Slurm。

### 1.3 科研范围的层次区分

- **单次科学工作流层面**：一轮新数据是否有必要触发 AI 模型训练；训练/推理会否改变下一轮模拟候选；在有限时间预算下何时安排 MD 与 AI。**这是 P1 的直接背景，也是用户强调的预测方向。**
- **集群资源层面**：在多个用户、任务和 CPU/GPU 节点之间分配资源，预测多硬件性能与竞争的影响。**这是总体博士蓝图的一部分，但不能未经决定写进 P1。**
- **科学反馈**与**系统反馈**不同：前者是新科学数据改善模型进而改变候选，后者是运行时长、资源使用、预测误差不断改进系统模型；不可混同。

## 2. P1：已经确认的研究对象和问题（最权威）

### 2.1 用户提供的日语原案（严格保留）

> FSD-EY（PDB: 1FME）を対象に、OpenMMで分子動力学計算を行い、得られた構造でCVAEを更新して、次の計算の出発点を選ぶワークフローを考えています。まずは既存のDeepDriveMD／Colmenaの実装を使い、小規模に動かせるか確認する予定です。
> 研究したいのは、2枚のGPUをMD計算と学習・推論で共有するとき、タスクの実行順序によって、同じ計算時間内の構造探索の結果がどう変わるかです。その前に、FSD-EYがこの研究に適した対象か、CVAEの更新が次の計算に役立つかをどう確かめるべきか、また科学的な成果をどう評価するのが妥当かについて、ご意見を伺いたいです。

**后续明确更新**：只有一块 GPU：`1× RTX PRO 6000 96GB`。不再按两块 GPU 设计 P1 正式实验。物理 GPU 只有一块；MIG 等功能不是已确认的必要研究内容。

### 2.2 P1 已确认项

| 项目 | 已确认事实 |
|---|---|
| 科学工作负载 | FSD-EY 小蛋白质 / PDB 1FME（实验载体，不是研究生物学问题） |
| 模拟软件 | OpenMM 分子动力学（MD） |
| 模型 | CVAE，根据 MD 结果更新并选择下一轮模拟起始构象 |
| 软件基础 | 优先利用 DeepDriveMD/Colmena 既有实现，先验证小规模闭环可运行 |
| GPU 硬件 | RTX PRO 6000，96GB 显存，**1 块** |
| 研究对象 | MD、训练与推理之间的任务执行时序 / GPU 计算时间竞争 |
| 固定预算 | 比较相同计算时间预算内不同策略的探索结果 |
| 科学产出 | 用户选择 **A：更充分地探索构象空间**，不是以找天然折叠结构为主 |
| 技术定位 | HPC 资源/时间调度与有效科研吞吐，不是蛋白质折叠方法或新的神经网络结构 |
| 当前助手任务 | 研究规划、设计与教学讨论；实现与环境操作交给独立 Codex |

### 2.3 P1 研究问题（不超范围的表述）

在单 GPU / 固定端到端计算预算下，如何安排 OpenMM-MD 与 CVAE 更新/推理（包括何时得到新数据、何时用数据更新模型、何时选下一轮模拟起点），是否会改变构象空间覆盖效率？

这不是关于多个 GPU 节点集群调度、集群未来作业到达率、大规模异构节点选择的研究。不要以三年总蓝图的远期目标覆盖该 P1 定稿。

### 2.4 P1 的先决科学与系统检验（用户原案明确提出，属于规划问题）

1. **实验载体适用性**：FSD-EY 的构象变化能否在可行 GPU 计算预算内产生可重复、可区分的探索信号？
2. **反馈是否有效**：CVAE 使用更新数据后，是否改变下轮候选结构选择；不同候选是否造成探索覆盖差异？不能仅看 CVAE train loss。
3. **结果怎么评价**：事先冻结不依赖每个策略自训练 CVAE 的统一构象覆盖定义，记录探索质量随总时间变化，而不依赖单次最好结果。
4. **系统调度是否真正有选择空间**：单卡串行任务若所有依赖顺序唯一，则无可优化顺序；需要明确可调的训练触发时机、训练次数、MD batch 数量、采样长度和等待/训练开销的机会成本。

### 2.5 可讨论、尚未最终确认的 P1 设计建议（不要当定稿）

- Baseline 候选：MD-only；CVAE 冻结模型；原 DeepDriveMD 固定阈值触发训练；不同训练触发时间；预算感知训练触发。是否全部实验、如何配置仍未由用户逐项确认。
- 推荐评价：在统一物理构象表征与固定划分下的构象覆盖范围/发现新状态数随**端到端墙钟时间**变化；累计模拟物理时间 ns、GPU 时间、训练/推理/数据处理开销为辅助指标；Native RMSD 可作诊断而非主目标。
- 实验需要多个随机种子、固定 MD 参数、CVAE 结构、起始条件、等价预算；最终种子数、时长、构象划分、数据过滤和误差条尚待实测后确定。
- 单 GPU 整卡上互斥执行 MD 与 CVAE 是最简单的基线，MIG/并发可作为后续候选，**不是已确认必做事项**。
- 目标文章可能是单 GPU 的工作流调度/性能案例研究；投稿场所 CANDAR、ICCS、HPC Asia 等此前只是助理建议，**尚未定稿或保证录用**。时间、CFP、篇幅和论文类型投稿前核实官方信息。

## 3. 用户原始的“预测”研究想法：科学反馈的未来价值（极重要）

### 3.1 历史观点与问题定义

2026-10-13 左右，用户提出“将科学反馈状态加入资源判断”：**新数据已经到达，但机器学习模型训练需要时间；现在更新模型能否在本次剩余科学计算期间影响候选选择？如果能显著改变候选选择，才可能值得延迟当前模拟。**

2026-10-23 多轮讨论中，用户又提出：
- 不应仅拿 AI 任务去填科学计算的空闲时间，训练可能完成得太晚，导致科学反馈没有时间兑现。
- 也不应在可利用的新数据到达前机械执行推理/更新；关键是判断旧/新模型对下一轮候选选择的影响。
- 根据历史十次模型更新结果（例如 6 次改善、2 次无变化、2 次恶化）估计下一次更新的收益，但要考虑历史概率样本小、效果幅度及当前状态差异。
- 前几次可使用数据阈值、小规模试验取得初步证据；后期剩余时间不足就停止训练。
- 将“继续 MD”与“训练一次再 MD”在固定剩余预算内**预期产生的科学成果**相比较，按收益/风险/机会成本选择。

用户最新明确纠偏：**预测主要是针对单次科学任务/反馈式科学工作流中的 AI 选择与训练更新决策**，不是以 HPC 集群未来任务提交量预测为主。此优先级必须写入未来论文规划。

### 3.2 研究预测的对象（区分）

**主要、用户强调的预测目标**：
- 新数据对 CVAE 更新的潜在收益；
- 更新后候选排序/起始结构的变化及其科学价值；
- 训练用时与剩余预算；
- 是否应该立即训练、推迟训练、直接继续 MD；
- 是否有足够剩余时间开展下一轮模拟以兑现更新的收益；
- 训练行为的预期效用与估计不确定性。

**次级、可用但尚未确认作为单独论文核心的预测**：
- 工作流任务的计算成本/运行时长预测；
- 不同硬件配置下的性能预测；
- 集群未来提交量/负载峰值/队列状态预测。上述最后一项主要由助理在扩展总体蓝图时提出；不要把它当用户的原定 P2。

### 3.3 形式化构想（仅作指导，不表示算法已确认）

决策发生在反馈到达后的某个状态 `s_t`。可能动作 `continue_MD`, `train_CVAE`, `run_inference`, `defer_update`，比较在剩余预算 `D-t` 下的后续构象探索收益，扣除训练和推理时间、数据准备/切换成本，并考虑收益的不确定性。重要的是**预测当前更新对后续科学决策有无价值**，而非仅预测 CVAE validation loss 或准确率。

这类反馈价值估计与 P1 的时序实验高度相关：P1 先测定真实的成本—收益与效果是否存在；后续论文若有足够独立贡献，可设计适度的反馈价值预测与决策策略，**未到 P1 完成时不应先固定论文编号和具体工作负载**。

## 4. 三年总研究蓝图（确定的愿景，具体论文分工为候选）

### 4.1 最终目标

固定、有限的科研计算资源下，通过合理的任务/资源配置使更多有效科学计算得到完成，同时兼顾硬件兼容性、科研用户权益、公平性、作业完成时间和资源开销。受 AI 算力需求增加影响的科研环境是动机，但**不要求传统科学计算都使用 LLM / AI**。

### 4.2 统一研究层次

- **工作流内任务时序与科学反馈价值**：何时 MD，何时模型更新、推理、选候选；单位资源/时间预算内的科学产出（P1 已明确）。
- **性能/资源需求与异构硬件匹配**：CPU/GPU 型号、内存与软件兼容、资源数量、任务执行边界、非线性加速、异构资源错配（总蓝图）。
- **长期统计辅助短期决策**：历史运行反馈用于更新成本/收益估计和决策方法，注意概率预测误差、模型更新价值不确定性；负载到达预测不应自动优先于用户强调的科学反馈收益预测。
- **集群级资源分配与公平性**：在一个 HPC 管理域下，任务放置、合法资源数量和启动顺序；用户授权配置下优化，不违背应用兼容性和科学正确性。

### 4.3 已讨论过的论文序列及最新待修订方向

**已讨论过但非用户最终批准的助理提案（需要纠偏）**：
- P1：阶段感知资源分配；P2：预测集群未来负载并进行多租户在线调度；P3：复杂科学工作流反馈联合优化；扩展 P4/P5。这个顺序是助理规划的候选，**与用户新明确的 P1 定稿及“预测主要针对单次科学任务 AI 更新选择”不完全一致**。

**更贴合用户意图的候选研究序列（以下绝非最终定稿）**：
1. **P1（已明确）**：1FME、OpenMM/CVAE、单 RTX PRO 6000，固定预算下比较 MD/AI 反馈任务时序与构象覆盖。
2. **下一篇候选：科学反馈价值预测和训练触发决策**：基于 P1 的观测，预测一次 CVAE 更新是否值得、是否能在剩余模拟时间改变候选选择；着重决策质量与预测误差，不盲目扩大到整个集群。
3. **进一步候选：异构 CPU/GPU 资源性能与调度**：资源匹配、资源数量、硬件兼容性、多任务资源共享，在受控或仿真集群研究。
4. **最后候选：将科学反馈任务价值与异构集群资源分配联合起来**：考虑多科学任务、公平性、竞争与长短期资源效率。
5. 若研究结果足够独立，可有附加论文（例如资源性能实证分析、鲁棒性）；不为达成五篇而碎片化。

**所有 P2+ 的具体生物/科学研究对象、实验程序、集群型号、数据集与主要算法，都要在 P1 完成后决定**。不得擅自定稿。不同论文可交换顺序，唯一必须保留的是原定 P1 和总体价值目标。

## 6. 证据与实验原则

### 6.1 论文不允许的论证捷径

- 不得把 GPU 利用率提高直接等同于科学产出提高。
- 不得仅报告 CVAE train loss 作为反馈价值；需要实际后续 MD 构象探索证据。
- 不得把随机运行之间的差异解释为调度因果影响：需同等资源/时间预算、事先固定评价、独立随机种子和适当不确定性报告。
- 不得把短任务数量简单与大规模任务完成数量直接相加声称科研产出更高；P1 在同一对象与统一指标内比较即可。
- 不得以人为设定的仿真参数直接当成真实 HPC 测量结论；需要明确校准来源和敏感性。
- 不得将 DeepDriveMD 固有的训练间隔参数调整当成未有人研究的新算法。论文可以是高质量的工作流性能与资源调度实证研究，不一定必须提出复杂学习算法。
- 不得宣称可对正在运行的 GPU/MPI 应用任意无成本变更资源。

### 6.2 P1 稿件的候选科研问题（尚待最终确认）

- RQ1：单 GPU 工作流中 MD/训练/推理/数据整理占用实际时间如何？
- RQ2：模型更新时机与次数如何影响相同计算预算的构象覆盖？
- RQ3：结合训练成本与剩余模拟预算，能否改善更新/继续 MD 的选择？

**优先级**：只有 P1 已确认的对象和大问题是定稿；RQ3 是否独立算法贡献，需要实测决定。
