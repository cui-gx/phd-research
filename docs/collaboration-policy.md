## 複数の研究支援者の役割と完全な引継ぎ

**CONFIRMED — 2026-10-26、研究者の追加指示。** 研究者は研究方向・実験目標・重要な科学判断を決定する。Codexはコード、サーバ実験、データ処理、テスト、再現、結果保管を担当する。ChatGPTは研究計画、方法論審査、実験結果の解釈、論文構成、次段階の設計を担当する。引継ぎ資料によって、会話の記憶に依存せず別の支援者が独立に確認できる状態を作る。

毎回の作業終了時に、実施内容、入力と版、実測・導出結果、失敗、未完了事項、次の優先課題を協作交接記録に残す。大規模実験の終了時には、その実験のディレクトリに以下の完全な日本語資料を新規作成または更新する。短い会話要約で代用しない。

- `review-dossier.md`：目的、承認範囲、事前設計と実行との差、データ系譜、モデル・対照・乱数、指標の数学的定義と単位、全主要比較、階層と不確実性、実費用、陰性・不一致・失敗、交絡、支持される仮説と支持されない仮説、外挿限界、次段階の条件と研究者への判断事項をまとめる。
- `handoff-to-chatgpt.md`：後述のA–Gを固定入口としてまとめ、詳細資料と原証拠の索引を示す。別の会話がその文書から審査を始められるようにする。

### 引継ぎ入口の必須構成

| 節 | 必須内容 |
|---|---|
| A 現在の状態 | バッチID、対象の実行・結果・最終報告のcommitを区別した版情報、最終同期SHA、`RUNNING / COMPLETE / PARTIAL / FAILED`、予定/成功/失敗/未実施数、最終検証時刻JST、GitHub反映範囲と許可保管先のみの範囲 |
| B 確認事項 | `CONFIRMED`＝研究者承認、`MEASURED`＝サーバ実測、`DERIVED`＝計算・解釈、`PROPOSED`＝未承認提案、`UNVERIFIED`＝根拠不足を区別し、出典を明示する |
| C 主要科学結果 | 実数、単位、分母、独立な統計単位、主要比較、方向の不一致、欠損、不確実性。結果が未完成なら暫定と明記する |
| D 主要技術情報 | 凍結プロトコル、実装入口、実行版、データ形式、モデル学習・復元、乱数、失敗・修正履歴 |
| E 残る論点 | 計画の変更につながり得る科学・方法・実装上のリスクと、ChatGPTに重点確認を求める問い |
| F ファイル索引 | 全重要報告、結果CSV/JSON、試験証拠、原データmanifestへの正確な相対パス、短い説明、利用可能性 |
| G 次段階 | 選択肢と必要条件を `PROPOSED` として提示し、研究者の承認待ち事項と禁止された自動実行を明記する |

### 証拠と完成状態の規則

主要な科学的結論には、読者が追跡できるCSV/JSON、固定版ソース、実行ログまたはmanifestへの有効なリポジトリ内相対リンクを付ける。大表を別ファイルに置く場合も、本文には解釈に必要な主要値、分母、統計単位、区間と限界を示す。存在しないファイルへ完成済みのようにリンクしない。

有利な実験条件だけを選ばず、正・負・不一致・識別不能・欠損を保存する。計算完了、集計監査、バックアップ、文書作成、科学審査、研究者の受入れは別の状態である。実行中は `RUNNING`、未完了の交付は `PARTIAL` とし、部分的な進捗を最終科学結論や全体 `COMPLETE` と表現しない。障害で終了した場合も、実測済み範囲・失敗・未実施の分母を維持する。

原データと凍結条件は報告作成のために変更しない。無許可の再実験や追加GPUタスクを実施しない。GitHubは可読資料・コード・簡潔な証拠を共有し、大型軌跡・モデル重み・完全原ログは許可保管先に置いてSHAと出典索引を示す。秘密鍵、内部ネットワークの詳細、実験室の私人情報を含めない。翻訳によって数式、単位、パラメータ、引用の意味を変えない。

同期の都度、通常のcommit/push後に遠隔回読し、実在するSHAを報告する。最終返信には最終commit SHA、二文書のパス、主要知見、不確実性、研究者が決める次の問いを含める。自文書のcommitを事前に捏造せず、実行版・結果版・報告版を混同しない。最終同期SHAはpush後の検証で確定し、引継ぎ本文の版情報とGit履歴・最終返信から照合できるようにする。
