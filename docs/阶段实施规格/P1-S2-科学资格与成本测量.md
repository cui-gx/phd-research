## 1. 固定研究边界

- 科学工作负载：FSD-EY，PDB 1FME。
- 现有科学工具：OpenMM MD、mdlearn CVAE、既有 DeepDriveMD 科学函数，Parsl 适配层可继续使用；**本阶段无需重新实现原版 Colmena 全套编排**。
- 资源：单块 RTX PRO 6000 Blackwell Max-Q 96GB；单 GPU 工作流；保留已验证的最小反馈闭环。
- 研究目的：有限 GPU 时间内 MD/AI 时序对**无监督构象空间探索**效率的影响。现在只做科学资格检查及成本测量，不做论文的优化算法或效果宣称。
- S1 参考测量：5×20ps MD、1 training、1 inference，29.607278 s 端到端；这仅是工程资格基线，绝不能当作正式科学协议。S1 原始证据不可改写。

## 2. 本阶段四项工作及交付

### S2-A 科学设置审计（先做，未完成前不得正式性能实验）

记录、核对并在新报告中呈现以下确切值与来源：
- 1FME 初始结构来源、NMR 模型编号、`unfolded` 起始结构的生成来源/方法；拓扑与残基、氢原子、终端、缺失原子、周期/盒子情况。
- OpenMM 使用的力场版本、溶剂（显式/隐式）、离子处理、cutoff、非键处理、约束、积分器/步长、温度控制、摩擦系数、能量最小化、平衡过程、速度产生或重启、输出间隔；记录可影响科学正确性的假设。
- 检查 MD 稳定性基础信号（能量/温度/NaN、结构/轨迹一致性、崩溃/约束失败），确认继续从中途 frame 重启是否确实保持规定的科学状态；仅恢复坐标和重新初始化速度与真正的动力学 continuation 不同，须如实命名为 reseeding/restarting。
- 汇总 `CONFIRMED` 的已有科研决策与 `UNVERIFIED` 的科学假设，不得悄悄变更 MD 力场、起始结构或 CVAE 架构来让输出看似更好。

交付：`science-protocol-audit.md`，配置与实际代码来源/commit，问题分级及必要修复建议。

### S2-B 单 GPU 实测任务成本与规模敏感度

- 从 S1 已验证的 20ps smoke 作为参照，设计至多两个**更长的、明确标记 PILOT** 的 MD 片段长度；长度及重复次数由执行端先在有界资源条件内合理选取并记录理由，不得将其视为正式论文参数。
- 先对一个短片段测试通过，再测更长片段；对于每个长度，尽可能采用相同科学配置、种子管理及 reporter 设置，记录实际 wall-clock、MD 初始化、积分/轨迹写出、数据分析、GPU/CPU 使用及安全性；冷启动与热启动、同步和进程启动边界明确。
- CVAE 训练/推理的实际成本：区分数据准备、模型加载/初始化、GPU 训练/嵌入、CPU LOF/排名、结果序列化和工作流调度/切换；采用当前已有配置作 PILOT，必要时增加明确标记为探索性的数据规模对照。
- 说明端到端耗时与任务内部耗时差值及不确定性；S1 的短任务初始化成本占比较高，**不得直接外推正式工作流计算效率**。
- 严格限制测试量并遵守共享服务器占用检查；不要批量发起长时 GPU 实验。

交付：原始测量、汇总 CSV/JSON、准确单位和复现指令、任务时间分解图/表、异常报告。不能只给估计值。

### S2-C 更新 CVAE 是否真正改变候选选择（有限可行性对照）

- 首先检查并记录当前上游选择链：`CVAE embedding -> LOF -> reference RMSD ascending`，明确参考构象（folded reference）是否参与实际候选排序及其位置。
- 把 **CVAE 更新效应** 与 **参考结构 RMSD 的筛选效应** 分开。对于对照，尽可能锁定相同的候选 MD 轨迹/frames、特征处理、LOF 和排序超参数以及随机种子。
- 尝试有凭据的 `frozen / before update` 与 `updated / after update` CVAE 比较：明确同一共同初始 checkpoint 的由来、新增训练样本、更新步骤与模型权重版本；对相同候选池记录嵌入、LOF 分值、选中 frame 的 ID、排序差异与训练/推理成本。
- 若现有代码并无真正的 freeze/update 对照入口，**先做最小可复现适配并报告**；若某项修改会实质改变科学决策规则，则只形成 `PROPOSED` 方案，不擅自纳入“已确认研究方法”。
- 本阶段只证明模型更新是否导致决策变化，不声称变化提高构象探索，也不强求统计显著性；若没有变化，也必须据实报告原因/置信限制。

交付：同候选池、同初始条件的 rank/selection 对照报告和成本；明确指标 `selection changed?` 不等于 `scientific benefit improved?`。

### S2-D 独立的构象空间覆盖评价方案（此阶段先设计和检验可计算性）

- 提出 1–2 个由**固定物理构象特征**定义、**与待比较 CVAE 和天然参考 RMSD 排序无关**的候选评价指标，例如固定接触图、Cα pairwise distances、二面角状态等。
- 清楚定义每种指标的结构对齐/距离/状态划分、输入轨迹、阈值选法、参考集合是否外部固定、聚类或离散化的统一规则、重复轨迹和计算成本；保证所有策略使用同一个评价器及同一规则。
- 用少量现有或 pilot 轨迹仅验证指标能计算、输入合法、不同状态不全退化成单一值；**不能用同一组比较结果去挑有利于某个策略的阈值**。
- 自然折叠参考结构 RMSD 可保留为**诊断**，不得作为 P1 的主科学成果或无监督探索的“oracle”选择基线而不说明信息泄漏。

交付：`coverage-metric-proposal.md`，样本输入/输出、限制及待研究者批准的最终指标与阈值。

## 3. 共享实验室服务器安全边界

- **每次服务器会话开始前**以及每次安装/提交 GPU 任务/重新启动之前，先只读核查他人任务和 CPU、内存、GPU 占用及预约信息（如有）；0% GPU utilization 不代表有使用许可。
- 有其他人占用目标资源或授权边界不清楚时暂停并报告，不抢占、不终止他人任务、不更改其文件。
- 仅使用个人拥有的运行目录、CPU/GPU 配额和已授权入口。SSH/VPN 错误遵照既有用户指令。不能在服务器上全局修改 Git 身份、CUDA、驱动或系统环境；保留初始成功闭环的原始证据。
- 任何时间/存储限制、异常终止、潜在科学不正确或无法复现，均应报告，不要隐瞒并继续批量运行。

## 4. 阶段完成与审查门槛

S2 的**完成**至少应提交四项各自可追溯的产物、真实执行记录/代码引用与失败记录，按事实分清 `MEASURED`、`PROPOSED` 和 `UNVERIFIED`：

1. `MD 协议`：明确每项物理/数值设置，基础稳定性资格及未解决的科学风险。
2. `计算开销`：至少有短/长 MD 的可复现测量并报告启动成本；训练、推理耗时分解；对共享 GPU 环境及采样测量限制有说明。
3. `模型更新`：有同一候选池的 frozen vs updated 的版本链、排名/候选差异与结果解释，或清楚的阻塞证据（不能伪造比较）。
4. `覆盖评价`：固定物理表征的指标草案与小样本可计算性证据，突出其独立性和阈值敏感性。

**本阶段不要求**：原生 Colmena 全工作流、构象覆盖显著改善、P1 正式调度算法、论文用正式大规模模拟、部署到多 GPU、实现集群负载预测。

执行端提交完成报告并将交接记录同步到 GitHub `main` 后停止，等待研究者与规划侧决定 S2 是否通过、是否进入 S3；不可自行冻结论文参数或自动启动正式比较。
