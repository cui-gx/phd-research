# 服务器优先的执行与复现规划

2026-10-25。平台分工 CONFIRMED；以下新增实现/实验均 PROPOSED，未执行。本次没有SSH会话，**不声称服务器当前空闲或有预约许可**。

## 1. 平台与边界

主平台为实验室已授权的单RTX PRO6000 96GB环境；实际设备UUID、驱动/功率模式、GPU名称和CPU配额需在每批许可时确认。复用现有项目与隔离环境，OpenMM/mdlearn/DeepDriveMD/Parsl版本从已保存manifest核对，不重新安装整套依赖，不因新方案改系统CUDA。

服务器执行经批准的MD、CVAE、结构特征、覆盖评价、CPU/GPU数值验证和真实时间测量。Mac负责代码/文档、SSH与传输、归档、GitHub、必要轻量调试。此前S2补充的Mac CPU测量保留原样，不能换标签成为目标GPU结果。连接失败按既有规则提醒开启校园VPN并停止排查；资源不明不得改在Mac上补算。

## 2. 每次执行前的硬门槛

1. 同步main，完整读AGENTS/总档案/交接/本批批准执行卡。批准状态、科学配置、资源上限任一缺失则不运行。
2. 进入服务器首先只读检查用户会话、CPU进程及归属、负载、可用内存、GPU进程归属/显存/利用率；核查实验室使用表与预约许可。零GPU利用率不证明可用。预约表无法访问时须研究者明确本次范围，不推断空闲。
3. 安装、测试、每批启动或恢复前再次检查，并与许可GPU UUID/CPU集合/有效期比对。发现他人占用或边界不清停止本人的新任务；不杀他人进程。
4. 只在本人项目隔离目录安装、写Git repository-local身份；不设全局Git，不保存密钥/密码到报告。既有SSH会话不关闭。
5. 试验运行中记录资源快照与本任务PID，许可到期/磁盘/内存上限按批准停止规则处理本人任务，失败日志先保留。

## 3. 已有能力与新增缺口（源码审查，非本次实测）

| 实现 | 当前可复用 | 正式B/C前需要什么 |
|---|---|---|
| `p1/server/science.py` | MD初始化/积分/输出分项计时，模型和优化器恢复、CUDA同步、哈希；坐标最小化+速度reseed | 经批准的松弛/资格过滤；严格匹配K步、曝光与输入划分的GPU配方验证 |
| `supplement_selection.py` | CPU小样本F0/F1/F2和无参考LOF比较 | 不能直接视为GPU正式科学方案；移入批准后的分支路径并检查参数恢复 |
| `runner.py` / `events.py` | 单worker、已发布数据/模型/排名关联，整任务available_at，H后结果排除、排空成本 | 冻结整个共同状态、动作分支、跨分支seed对照、按根数据契约；不可改用smoke成功就停的模式 |
| `qualification*.py` / supplement评价 | 已有S2输出及候选物理特征 | 独立资格审查、物理阈值、结果可计规则；旧脚本通过不等于新指标合格 |
| `policy.py`及累计结果触发 | 部分事件/截止语义基础 | 强基线调优、统一完整成本保护、状态规则均未按本设计实现/验收 |

现有runner的`available_at_s`是控制器观察整任务成功后的时刻，是合适的保守批次边界。S2专用输出不一定有完整同类发布记录，不能事后用worker结束时刻替代所有可用事件。**不需要为本研究先做逐帧流系统**；最小方案统一整批发布即可，但资格检查必须纳入发布路径。

## 4. 日志与时间账

所有时间使用同一campaign单调墙钟；另存UTC用于审计，跨机器时间不能直接作精细耗时差。保存 task submitted/start/end、数据可用、模型发布、推理完成/排名发布、MD采用模型、资格检查完成、截止、排空结束。仅任务结束而未可读/未资格通过不得计结果。

worker分项相加形成其墙钟；嵌套checkpoint-write已经包含于fit，不能再加一次。提交→可用减worker时间称“进程外残余”，含启动、序列化、轮询等，不称纯调度开销。重叠阶段使用关键路径/占槽区间并集，不盲目相加；本次单槽计算无同时MD/训练，CPU控制及I/O仍可能重叠。

输出账同时包含：h内成果、有效MD ns、全部MD ns（含松弛/失败/排空）、训练/推理次数、特征成本、CPU时间、GPU占槽墙钟、实际GPU活动采样、预约时长、排空成本。利用率是诊断，不是科学目标。

## 5. 文件布局与复现

新批次在本人目录建立不可覆盖run_id子目录：approval+manifest、inputs引用、snapshot、branches、events、metrics、failures、hashes。本设计不创建run，不猜测远端绝对路径。共享记录使用逻辑artifact ID，实际存储位置在私有执行清单中管理，避免GitHub上传服务器网络细节。

每批固定code SHA及dirty状态（正式运行应无未记录改动）、依赖lock与实际import版本、CUDA/driver/OpenMM platform、PyTorch/mdlearn/DeepDriveMD来源SHA、科学配置SHA、全部seed及来源分组、数据/权重SHA-256、评价器版本、批准卡ID。日志与小型结构化结果上传GitHub；DCD/大权重存服务器和授权本地备份，双端哈希后确认传输。不以“GitHub有manifest”声称大数据已上传。

复现顺序为：检查许可与资源→核对manifest和输入哈希→恢复已冻结状态→按批准分支表执行→验证事件和输出→独立评价→生成报告与失败表。重复运行用新run_id，旧结果只读。dry-run/单元检查、科学资格、真实实验三种结果分别命名。
