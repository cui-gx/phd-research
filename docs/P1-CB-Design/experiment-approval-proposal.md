## 2. GQ最小候选与资源上限

**候选采样**：4个独立随机根，每根1段L_q ns；其中2根用于构建/调节评价，2根用于只读资格检查，不拆帧代替留出。L_q=1ns仅用于算预算的示例，须由科学意见确认是否有足够有效采样；所有根若共用同一准备结构，结论只条件于该结构。松弛部分与可计采样分开，资格不足时不声称“已有四根所以通过”。

**候选成本资格**：最多2种科学上可接受的续训配方，各2个训练seed，每个随后1次推理，共≤4训练+4推理。配方由独立数据上稳定性和物理选择解释确定，不能以让训练更贵为目标。使用既有MD数据或GQ校准根，资格留出不参与配方选择。FSD-EY的首个可信下游作用仍由B1检验，GQ仅是配方合法性/成本筛选。

候选预约上限1 GPU小时，CPU最多3个获准逻辑核、16GiB内存、输出5GiB，均需实际许可/环境核对；不是已获资源。硬上限不足以完成时保留失败并提新申请。1小时包含安装/测试/资格任务实际占用与排空；不能只算积分。训练单任务上限120s是执行保护候选，不是科学训练长度要求；若合格配方预计更长，应在运行前改审批卡，不中途偷偷截短模型。

以S2 worker均值作**DERIVED粗量级**：4×74.2386≈297s，未含新松弛、完整发布、特征/评价、环境开销。它仅说明4ns积分本身不应被误称长时采样，不保证1小时足够或科学合格。不得用Mac训练时间估算GPU成本。

## 3. GB1任务清单与预算依据

PROPOSED诊断规模：4个新的独立campaign根×2个预定状态×2个成对seed块×3臂。

- 下游MD：48段，每段L ns，最小k=1。
- 更新：F1/F2各16次，共32次；推理48次。
- 父历史：预算例为每根2段L，共8L ns。若产生科学状态需要更长历史，必须据真实生成政策重新核算。
- 初始模型：使用独立校准来源的冻结公共初值；训练/构建费用另列。若每根需不同初值或历史更新，增加实际任务数，不隐去成本。

总MD示例q_total=56L ns。若L=1ns且成本仍接近S2，MD worker约4,157s≈69.3min。总成本规划公式：T≈T_prepare+56d+32c_train+48c_infer+T_features+T_eval+T_external+T_drain，其中d在正式报价时使用完整MD服务时间；若已经含进程外成本，T_external只加未含部分，避免双计。

候选预约上限4 GPU小时、3逻辑CPU、16GiB、20GiB输出。**4小时只是待审上限，不是可完成承诺**；GQ后代入目标GPU实测配方成本，若不够应先调整申请/缩减明示的诊断规模，不能删除失败臂或中途改变h。在全部48分支之前，首个完整三臂块仅检查恢复/日志/合法性；出现P0科学或配对错误停止整批。不得根据首块谁赢来选其余状态。

4个根用于可辨性和方差诊断，不做“统计上已证明C”的宣称。2个seed块是重复性检查，不把48段称48次独立campaign。

## 4. GB2/C的数据与成本场景

GB1根可以继续作为开发源；若先看过B1选择状态，再做B2，属于自适应开发，不能称确认性试验。最小场景仍为4根×2状态×2seed块×3动作×2horizon=96个分支run。示例h∈{4d,12d}，对每个h有48run，评价窗口总量为48×(4+12)d=768d。

仅用74.2386s暂代d，窗口总量约15.84 GPU小时，**还未含前置历史、排空、校准和独立确认**，正式d可能更长。故不应把B2/C说成“几分钟就能完成”的实验。候选24GPU小时预算仅用于讨论量级，必须以GQ实际成本、科学有效时域重新报价；当前不申请自动使用24小时，也不预留机器。各run另有任务数和存储上限，实施卡批准后才产生具体队列。

C的最终未见验证根数不在此虚构固定值。先按根级方差、领域δ、状态共同支持、留出精度确定n_dev/n_test，并批准最大根数/总时间。4根诊断的交叉验证只能探索；不能在4根上调参数又给“独立验证PASS”。如果预算只能支付这4根，就交付有限诊断，放弃确认性表述。
