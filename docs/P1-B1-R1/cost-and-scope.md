# 費用見積りと承認すべき最小範囲

2026-10-28。以下はPROPOSEDの事務的見積りで、実測でも予約でも実行許可でもない。本輪はサーバ接続0、科学数値計算0、GPU利用0である。

## 根拠と規模

既存[費用報告](../P1-B1-Expansion/cost-and-runtime.md)では240枝評価のwall合計3,866.478 s、平均16.110 s/枝、範囲10.261–21.652 s。これは当時の環境/処理全体の測定で、今回の単一CPU・参照変更・I/O費とは同一でない。raw全archiveは20,223,932,863 bytesという**圧縮容量**であり、必要作業領域を示さない。

提案は4参照法×240枝（論理上960評価）。同一参照の重複を共有できるため、全960を独立に再計算する必要はない。全指標/時間窓を一度求めた距離配列から派生する。LOFはFULL80確認+S8の2制限×40=80新fit、計160 fit。新embedding・学習・MDは0。

|項目|見積り/運用案|不確かさ|

|元評価再現と共通参照評価|単一CPUで概ね2–6時間の計画枠|旧1参照パス約1.07時間を参照。参照点数減少/再利用で短縮し得るが、単thread化/I/O/離散再走査で増える|
|索引監査・候補LOF・階層集計/図|上記に加え10–60分の作業余裕|保存embeddingの利用可否、近傍探索方式、共有I/Oは未測定|

|空きディスク|元の100 GiB保護基準を維持する提案|容量不足なら全archive展開を試みず停止。上限は原証拠を消して満たさない|

距離計算量は各枝についてO(N_branch×N_reference×325)、メモリはblock処理で抑える。上表の速度をGPU効果やB2の機会費用へ流用しない。

## 実行許可後の段階的停止案

1. CPU実行の明示承認と本人領域/共有資源を確認。保存済み配列のSHA/shape監査を先行する。
2. 全240の固定行列から事前指定の先頭枝で元評価/1新参照の工程検査を行う。この枝は最終全条件の一部で、効果の符号を選別に使わない。
3. 初期処理の実wall/CPU/RSS/I/Oを測り見積りを更新する。6時間を超える見込み、RSS/容量の逸脱、他者利用との競合は停止して残量を報告する。この6時間はPROPOSEDなCPU運用再審査点であり、既存GPU長期規則の変更ではない。
4. 研究者が承認した範囲を完了し、原SHA不変/全表/欠損/ログを検査して停止する。別batchや新科学実験は始めない。

SSH失敗時はVPN依頼だけに留める。既存controller/collectorを起動せず、Mac raw backupを復活させず、サーバ原archiveや旧環境を削除しない。必要データがarchiveにしかない場合は、本人の新作業領域へ必要メンバーだけを取り出す手順と空き容量を先に確定する。バックアップ方針は[現行規則](../P1-B1-Expansion/storage-and-delivery-policy.md)のまま。

## 別申請が必要なもの

新しいMD、別起点の下流対照、M0を交差させる再学習/再推論、学習十分性の実験、物理条件変更、独立根追加、B2/C/S3はこの費用枠に含まない。これらの価格や所要時間を既存240枝から推測で確約しない。必要性を[未識別事項](unidentified-confounders.md)として示すだけである。
