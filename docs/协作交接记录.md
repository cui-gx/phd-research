## 2026-10-23 — 模型档位选择建议（PROPOSED，尚未确认为固定规则）

- **讨论背景**：用户反馈持续使用 Astra Ultra，但实际工作推进量偏少，希望按博士研究、代码实现、文献、日常事务区分模型与推理档位。
- **建议**：Work/Codex 的日常 P1 开发、单文件或局部修复、测试和 Git 同步优先使用可选的 GPT-6.1 Sol Medium/High（不可用则选 5.6 Sol）；明确重复任务可以选 Luna/Terra。跨依赖复杂排障、关键系统架构设计使用 Astra Light/Medium/High；Max 留给单任务深度困难推理；Ultra 仅用于能够真实拆成多个可独立执行、可检查的子任务的大型工作，不作为默认档位。
- **与研究规划的分工**：在本规划对话，普通方案讨论以 GPT-6 High 为主；复杂研究审查才提升至可用的更高档位。模型选择不改变科研目标、工作流范围或科学结论。
- **重要区分**：Ultra（并行子智能体）≠ Ultrafast（响应速度服务）；模型可用性和用量以账户实际菜单为准。
- **状态**：`PROPOSED`，仅作为效率建议，不要求实施端擅自变更用户已选模型和权限设置。

**初步阶段预设验收门槛（工作定义，细节随真实实现核对）**：

- 选出的结构确实被用作下一轮 OpenMM MD 的起点，证明至少一轮闭环；
- 全部 GPU 计算在 1× RTX PRO 6000 96GB 可访问资源限制内执行，并正确处理任务资源竞争；

**通过后建议的下一阶段（PROPOSED，未批准）**：单 GPU 完整工作流性能分解和 CVAE 反馈是否改变后续候选的可行性测量。固定科学设置、记录 MD/数据处理/训练/推理耗时与真实 GPU 使用，再与研究者确定正式资源调度对照和构象覆盖评价标准。
